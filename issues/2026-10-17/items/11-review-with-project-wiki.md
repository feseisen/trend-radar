# 11 AIのコードの点検に、案件固有の知識を足す（過去の指摘から「点検用の手引き」を育てる）

号: 2026-10-17 ／ 判定: **採用**（新顔。手順はこの号で組み立てた） ／ 確かめた日: 2026-10-17

## 人向けの概要

- **何か**: AIにコードの点検（レビュー）をさせるとき、コードだけでは分からない **設計の判断や案件の決まり** を、過去のレビューの記録からまとめた手引き（Wiki）にしておき、点検のときに関係する所だけ読ませるやり方（[Zenn の記事、株式会社ラグザイア](https://zenn.dev/luxiar/articles/5ba317758861eb)、2026-10-09）
- **測った結果**（記事の値）: 実際の PR 24件で、人が「直すべき」と指摘した 42件を正解として比べた
  - 手引きなし: 13件が一致または近い（31%）
  - 手引きあり: 21件が一致または近い（50%）
- **なぜ取り上げるか**: 数字で比べていて、やり方が他の職場にも写せる。道具は Claude Code
- **取り入れると何が良くなるか**（推測）: AIの点検が「一般論の指摘」から「この案件で本当に問題になる指摘」に寄る。人の点検の手間が減る
- **手間**: 手引きの最初の版を作るのに、過去の指摘の量しだいで数十分〜数時間
- **気をつけること**: 記事も 50% で止まっていると書いている。**AIの点検は人の点検の代わりではなく下ごしらえ**。記事には設定やファイルの形が載っていないので、下の手順はこの号で組み立てたもの（まだ試していない）

### 対応環境

| | |
|---|---|
| 使える AI | Claude Code（記事で使われた道具）。考え方はどの AI でも使える |
| 要るもの | 過去のレビューの記録（PR のコメントなど） |
| ネット・API キー | 追加は無い |
| 外への送信 | 無い。ただし手引きに社外秘が入るので、置き場に注意 |

## 生成AI向けの詳細

> ここから下を、そのまま AI に渡してください。手順は記事の考え方をもとにこの号で組み立てたもので、記事の筆者の設定そのものではありません。

### あなた（AI）への依頼

利用者のリポジトリに「点検用の手引き」を作り、以後のコードの点検でそれを使ってください。進め方は次の4段です。各段の終わりに利用者に見せて、次へ進んでよいかをもらってください。

### 1. 材料を集める

- 過去の PR のレビューのコメントのうち、**直す必要があった指摘** を集める（「LGTM」や雑談は除く）
- 1件ごとに: どのファイルのどんな変更への指摘か、指摘の中身、なぜそう直すべきか、PR のリンク
- 集める道具が無い（GitHub に触れない）なら、利用者に指摘の写しを貼ってもらう

### 2. 手引きにまとめる

リポジトリの中に置く（例）:

```
docs/review-wiki/
  index.md        ← 1行1項目の目次。項目名・どんな変更で効くか・ファイル名
  <項目>.md       ← 1項目1ファイル
```

1項目のファイルの形（例）:

```markdown
# <決まりの名前>

- 効く変更: <どんなファイル・どんな変更のときに読むか>
- 決まり: <一文で>
- 理由: <なぜそうするか。コードからは読めない背景>
- 良い例 / 悪い例: <短いコード>
- 元の指摘: <PR のリンク>（複数可）
```

まとめるときの決まり:

- **同じ趣旨の指摘は1項目にまとめ、元の指摘を全部リンクする**（何回指摘されたかが重みになる）
- コードを読めば分かること（書式、命名の一般論）は入れない。それは整形の道具や一般の点検で足りる
- 決まりと理由を分けて書く。理由の無い決まりは、後で外してよいか判断できない

### 3. 点検のときに使う

プロジェクトの `CLAUDE.md`（または AI への常設の指示）に、次の趣旨を足す:

```markdown
## コードの点検
点検の前に docs/review-wiki/index.md を読み、変更されたファイルと変更の種類に関係する項目だけを開く。
指摘ごとに、手引きのどの項目に基づくか（無ければ「一般の観点」）を書く。
```

**全部の項目を毎回読ませない。** 目次で選ばせる（関係の無い中身は量そのものが雑音になるため。推測）。

### 4. 効き目を測る（記事と同じ形）

1. 過去の PR を 10〜20件選ぶ（手引きの材料に使っていないもの）
2. 人が付けた「直すべき指摘」を正解とする
3. 手引きなし・ありで AI に点検させ、正解と一致または近い指摘の数を数える
4. 結果を「なし ○件（○%）／あり ○件（○%）」で利用者に渡す。件数が少ないことを書く

### 5. 育て方

- 人の点検で、AIが見落とした指摘が出たら、手引きに足す候補として集めておき、まとめて足す
- 古くなった決まり（もう使っていない仕組みの決まり）は、消さずに「廃止」と理由を書く

### 注意

- 手引きは案件の内情そのもの。リポジトリの外（公開の場、外部のサービス）に出さない
- AIの点検の結果を、そのまま人の点検の代わりにしない。記事の値でも一致は 50%
