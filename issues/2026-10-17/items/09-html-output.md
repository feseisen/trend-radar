# 09 AIの出力を Markdown ではなく HTML 1枚にする

号: 2026-10-17 ／ 判定: **採用**（新顔ではない。設定なしで今日から試せる） ／ 確かめた日: 2026-10-17

## 人向けの概要

- **何か**: AIに計画・比較・報告・説明を頼むとき、文章（Markdown）ではなく **ブラウザで開く HTML 1枚** で出させるやり方。表・図・折りたたみ・タブ・コピーのボタンを1枚に入れられる
- **なぜいま話題か**:
  - Anthropic の Thariq Shihipar 氏（紹介記事の肩書きでは Claude Code のエンジニアリングの責任者）が「HTML のほうが効く」という長文を X に出し、Anthropic の社内でも計画・コードの点検・報告の既定を HTML にしている、と紹介された（[紹介記事](https://pasqualepillitteri.it/en/news/2243/html-vs-markdown-claude-code-thariq-anthropic)。記事の題では 2026年5月。本文の日付は読み取りが食い違ったので確定させない）
  - 10月に GitHub で伸びた道具の多くが、出力を「HTML 1枚」にしている（05 の図、03 の立体図、02 の動画の元）
- **取り入れると何が良くなるか**（記事の主張と推測）: 長い文書が読みやすくなる（記事は「Markdown は 100 行を超えると読みにくい」）。リンク1つで誰でも開ける。選択肢をボタンにして、選んだ結果をそのまま次の頼みにできる
- **手間**: 設定は要らない。「HTML 1枚で」と頼むだけ
- **気をつけること**: **自分で何度も直す文書は Markdown のまま** がよい（HTML は直しにくく、Git の差分も読みにくい）。記事の書き手も「他人が読むなら HTML、自分で直すなら Markdown」としている

### 対応環境

| | |
|---|---|
| 使える AI | どれでもよい。Claude Code、claude.ai（アーティファクト）、ChatGPT など |
| 開く場所 | ブラウザ |
| ネット | 外部の部品を使わなければ要らない |
| API キー | 要らない |
| 外への送信 | 無い（外部のフォントや部品を読まなければ） |

## 生成AI向けの詳細

> ここから下を、そのまま AI に渡してください。

### あなた（AI）への依頼

利用者への出力が次のどれかなら、**HTML 1枚** で出してください。それ以外は今までどおり文章で返してください。

| HTML にする | 文章（Markdown）のまま |
|---|---|
| 複数の案の比較、計画（日程・危険の表つき） | 短い答え |
| コードの変更の説明、点検の結果 | コードだけの返事 |
| 図が要る説明、仕組みの説明 | 数行で済む内容 |
| 状況の報告、出来事の時系列 | 利用者が自分で何度も書き直す文書 |
| 一回きりの入力用の画面（選んで結果を写す） | |

（この表は、紹介記事の「HTML が向く」「Markdown のままがよい」の整理と、html-artifacts スキルの例外の考え方をまとめたもの）

### HTML 1枚の決まり

1. **1つのファイルで完結させる。** CSS と JavaScript は中に書く。画像は SVG で描くか、埋め込む
2. **外への読み込みをしない**（既定）。フォントはシステムのものを使う。日本語なら例えば:
   `font-family: system-ui, -apple-system, "Segoe UI", "Hiragino Sans", "Yu Gothic UI", Meiryo, sans-serif;`
   外部の部品がどうしても要るときは、利用者に断ってから、版を固定して読む
3. **いちばん上に、読む人が知るべきこと** を置く。決めてほしいことがあるなら、それを1行目に
4. **長いものは畳む。** 詳細は `<details>` で折りたたむか、タブに分ける
5. **写して使うもの（命令・住所・文）は、1つずつ囲み、コピーのボタンを付ける**
6. **表は見出しを固定し、横にはみ出すときは表の中だけで横に動かす**（ページ全体を横に動かさない）
7. **明るい画面と暗い画面の両方** で読めるようにする（`prefers-color-scheme`）。文字と背景の差を十分にとる
8. **印刷しても崩れない**（`@media print` で畳んだ中身を開く、色の背景を落とす）
9. **スマートフォンの幅でも読める**（左右に 16px ほどの余白、横のはみ出し無し）
10. **元のデータは、ページの中に分けて持つ**（`<script type="application/json" id="data">…</script>`）。後で直すときに、表示と中身を分けて扱える

### 見た目をそろえたいとき

紹介記事の勧め: 一度「design-system.html」（色・文字の大きさ・部品の見本を並べた1枚）を作り、以後の頼みで「この見本に合わせて」と添える。

### 選択肢を選ばせて、次の頼みにする形

比較や設定の画面では、選んだ結果を「AIへの次の頼みの文」として組み立て、コピーのボタンで写せるようにする。利用者はそれを貼るだけで次に進める。

### 道具ごとの出し方

- **Claude Code**: ファイルとして書き、パスを伝える。開くための命令が要るなら1つだけ示す
- **claude.ai**: 「HTML のアーティファクトで」と頼まれた形で出す
- **ChatGPT など**: HTML のファイルとして出す（そのまま保存して開けるように）

### スキルとして決まりを固定したいとき（任意）

- [dogum/html-artifacts](https://github.com/dogum/html-artifacts)（Apache-2.0）: 「HTML のほうが伝わる頼み」を見分け、例外（短い返事、コードだけ、数行のもの）では Markdown に戻すスキル。claude.ai には設定 → Capabilities → Skills から `.skill` を上げる。星 136・フォーク 13・コミット 2 と小さい
- Claude Code の公式のマーケットプレイス（`anthropics/claude-plugins-official`）に、対話的な HTML の「playground」（つまみを動かすと見本が変わり、結果を頼みの文として写せる1枚）を作るプラグインがある、と別の掲載サイトに出ていた。**公式の側では確かめていない。** 入れるときは `/plugin` の一覧で名前を確かめる
