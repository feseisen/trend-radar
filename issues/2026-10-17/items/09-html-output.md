# 09 AIの出力を Markdown ではなく HTML 1枚にする

号: 2026-10-17 ／ 判定: **採用**（新顔ではない。設定なしで今日から試せる） ／ 確かめた日: 2026-10-17

## 人向けの概要

- **何か**: AIに計画・比較・報告・説明を頼むとき、文章（Markdown）ではなく **ブラウザで開く HTML 1枚** で出させるやり方。表・図・折りたたみ・タブ・コピーボタンを1枚に入れられる
- **なぜいま話題か**:
  - Anthropic の Thariq Shihipar 氏（紹介記事の肩書きでは Claude Code のエンジニアリングの責任者）が「HTML のほうが効く」という長文を X に投稿し、Anthropic の社内でも計画・コードレビュー・報告の既定を HTML にしている、と紹介された（[紹介記事](https://pasqualepillitteri.it/en/news/2243/html-vs-markdown-claude-code-thariq-anthropic)。記事のタイトルでは 2026年5月。本文の日付は読み取りが食い違ったので確定させない）
  - 10月に GitHub で伸びたツールの多くが、出力を「HTML 1枚」にしている（05 の図、03 の立体図、02 の動画の元）
- **取り入れると何が良くなるか**（記事の主張と推測）: 長い文書が読みやすくなる（記事は「Markdown は 100 行を超えると読みにくい」としている）。リンク1つで誰でも開ける。選択肢をボタンにして、選んだ結果をそのまま次の指示にできる
- **手間**: 設定は要らない。「HTML 1枚で」と頼むだけ
- **気をつけること**: **自分で何度も直す文書は Markdown のまま** がよい（HTML は直しにくく、Git の差分も読みにくい）。記事の筆者も「他人が読むなら HTML、自分で直すなら Markdown」としている

### 対応環境

| | |
|---|---|
| 使える AI | どれでもよい。Claude Code、claude.ai（アーティファクト）、ChatGPT など |
| 開く場所 | ブラウザ |

## 生成AI向けの詳細

> ここから下を、そのまま AI に渡してください。

### あなた（AI）への依頼

利用者への出力が次のどれかなら、**HTML 1枚** で出してください。それ以外は今までどおり文章で返してください。

| HTML にする | 文章（Markdown）のまま |
|---|---|
| 複数の案の比較、計画（日程・リスクの表つき） | 短い答え |
| コードの変更の説明、レビューの結果 | コードだけの返事 |
| 図が要る説明、仕組みの説明 | 数行で済む内容 |
| 状況の報告、出来事の時系列 | 利用者が自分で何度も書き直す文書 |
| 一回きりの入力用の画面（選んで結果をコピーする） | |

（この表は、紹介記事の「HTML が向く」「Markdown のままがよい」の整理と、html-artifacts スキルの例外の考え方をまとめたもの）

### HTML 1枚の決まり

1. **1つのファイルで完結させる。** CSS と JavaScript は中に書く。画像は SVG で描くか、埋め込む
2. **外部のファイル（フォント・ライブラリなど）を読み込まない**（既定）。フォントはシステムフォントを使う。日本語なら例えば:
   `font-family: system-ui, -apple-system, "Segoe UI", "Hiragino Sans", "Yu Gothic UI", Meiryo, sans-serif;`
   外部のライブラリがどうしても要るときは、利用者に断ってから、バージョンを固定して読み込む
3. **いちばん上に、読む人が知るべきこと** を置く。決めてほしいことがあるなら、それを1行目に
4. **長いものは畳む。** 詳細は `<details>` で折りたたむか、タブに分ける
5. **コピーして使うもの（コマンド・URL・文）は、1つずつ囲み、コピーボタンを付ける**
6. **表は見出しを固定し、横にはみ出すときは表の中だけを横スクロールさせる**（ページ全体を横スクロールさせない）
7. **ライトモードとダークモードの両方** で読めるようにする（`prefers-color-scheme`）。文字と背景のコントラストを十分にとる
8. **印刷しても崩れない**（`@media print` で畳んだ中身を開く、背景色を消す）
9. **スマートフォンの幅でも読める**（左右に 16px ほどの余白、横のはみ出し無し）
10. **元のデータは、ページの中に分けて持つ**（`<script type="application/json" id="data">…</script>`）。後で直すときに、表示と中身を分けて扱える

### 見た目をそろえたいとき

紹介記事の勧め: 一度「design-system.html」（色・文字の大きさ・部品の見本を並べた1枚）を作り、以後の依頼で「この見本に合わせて」と添える。

### 選択肢を選ばせて、次の指示にする形

比較や設定の画面では、選んだ結果を「AIへの次の指示文」として組み立て、コピーボタンでコピーできるようにする。利用者はそれを貼るだけで次に進める。

### ツールごとの出し方

- **Claude Code**: ファイルとして書き、パスを伝える。開くためのコマンドが要るなら1つだけ示す
- **claude.ai**: HTML のアーティファクトとして出す
- **ChatGPT など**: HTML のファイルとして出す（そのまま保存して開けるように）

### スキルとして決まりを固定したいとき（任意）

- [dogum/html-artifacts](https://github.com/dogum/html-artifacts)（Apache-2.0）: 「HTML のほうが伝わる依頼」を見分け、例外（短い返事、コードだけ、数行のもの）では Markdown に戻すスキル。claude.ai には「カスタマイズ → スキル」からアップロードする（入れ方は 04。README は英語の画面名 Settings → Capabilities → Skills で書いていて、`.skill` のファイルも挙げている）。スター 136・フォーク 13・コミット 2 と小さい
- Claude Code の公式のマーケットプレイス（`anthropics/claude-plugins-official`）に、触って操作できる HTML の「playground」（つまみを動かすと見本が変わり、結果をプロンプトとしてコピーできる1枚）を作るプラグインがある、と別の掲載サイトに出ていた。**公式のマーケットプレイスでは確かめていない。** 入れるときは `/plugin` の一覧で名前を確かめる
